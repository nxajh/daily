## 为什么需要这套流程

很多人有一个共同的问题：**模式识别能力很强，但从'看清问题'到'执行方案'之间的转化效率很低。**

具体表现为：

- 遇到问题瞬间找到解，然后直接执行——不做备选方案评估
- 习惯性采用固定模式处理新问题，即使情况已有不同
- 信息量大时关键信息提取效率下降
- 多角度拆解能力不足，策略性思考欠缺

这不是能力缺失。大多数情况下，你的大脑完全有能力生成多个视角。问题在于**默认程序跳过了多角度评估这一步**——从"识别规律"直接跳到"执行方案"，中间的"生成备选、评估权衡"环节被省略了。

## SMART 框架

UT Dallas Center for BrainHealth 开发的 **SMART（Strategic Memory Advanced Reasoning Training）** 是目前研究最多的策略性推理训练程序，发表在多个 NIH 资助的研究中。它的核心不是教知识，是教**元认知策略**——改变你处理信息的方式。

SMART 的三个核心策略：

1. **Strategic Attention（策略性注意）**：从信息中区分重要和不重要的部分，主动删减噪音
2. **Integrated Reasoning（整合推理）**：从具体信息中提炼高层含义，从不同角度整合信息
3. **Innovation（创新性思维）**：从不同视角看待同一问题，生成备选方案

以下是基于 SMART 框架整理的标准化实践流程。

---

## 流程一：决策前强制暂停（每次重要决策，3-5 分钟）

**触发条件**：当你心里已经有了一个明确方案，准备执行或提案时。

### Step 1：写下你的方案（1 分钟）

> 我要：______
> 因为：______

### Step 2：生成两个备选（2 分钟）

强制写出另外两个可能的方案。不要求高质量，要求**存在**。

> 方案 B：______
> 方案 C：______

卡住了就问自己：
- 如果方案 A 不可行，我第二个选择是什么？
- 如果我是一个完全不同的人（竞争对手/客户/上级），我会怎么做？
- 如果预算/时间减半呢？翻倍呢？

### Step 3：快速评估（1 分钟）

| | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 成本 | | | |
| 风险 | | | |
| 可逆性 | | | |

如果方案 A 在三个维度上都不是最优的——重新选择。

---

## 流程二：多角度拆解（面对复杂问题时，10-15 分钟）

**触发条件**：遇到不是一眼能看清的问题时。

### Step 1：问题陈述（2 分钟）

用一句话写出你要解决的问题：

> 问题是：______
> 期望的结果是：______

### Step 2：三个视角（5 分钟）

强制从三个不同角度分析这个问题：

| 视角 | 这个角度看，问题是什么 | 这个视角的优先级是什么 |
|---|---|---|
| 我的视角 | | |
| 对手/竞争者的视角 | | |
| 第三方/旁观者的视角 | | |

### Step 3：约束条件（3 分钟）

列出限制你选择的硬约束：

- 时间约束：______
- 资源约束：______
- 不可改变的事实：______

### Step 4：组合方案（5 分钟）

从三个视角的交集中，找出一到两个可以满足多数约束的方案。

> 最优方案：______
> 备选方案：______
> 可能的副作用：______

---

## 流程三：信息处理降噪（面对大量信息时，5 分钟）

**触发条件**：开会、看报告、处理邮件/消息时，感觉信息量大。

### Step 1：删减（2 分钟）

拿到信息后第一件事：**划掉一半。**

> 这些信息中，无关的/已知的是：
> - ~~xxxxx~~
> - ~~xxxxx~~
> - ~~xxxxx~~

### Step 2：分组（2 分钟）

剩下的信息分成最多三组：

| 分组 | 内容 | 重要性（高/中/低） |
|---|---|---|
| 组 1 | | |
| 组 2 | | |
| 组 3 | | |

### Step 3：提炼（1 分钟）

一句话概括每组的核心意思：

> 组 1 的核心：______
> 组 2 的核心：______
> 组 3 的核心：______

---

## 流程四：周复盘（每周一次，15-20 分钟）

**触发条件**：每周固定时间（建议周五下午或周日晚上）。

### Step 1：本周决策回顾（5 分钟）

列出本周做出的 2-3 个重要决策。

| 决策 | 当时考虑了几个方案 | 实际用了哪个 | 如果重来会怎么做 |
|---|---|---|---|
| | | | |
| | | | |

重点看第二列（"考虑了几个方案"）。如果几乎全是"1 个"，说明你在执行阶段没有做备选评估。

### Step 2：固定模式识别（5 分钟）

> 这周有没有遇到"凭经验直接处理"的情况？
> 那个情况和我之前处理的案例有什么**不同**？
> 我有没有忽略这个不同？

> 情境：______
> 我用了固定模式：______
> 实际上这次的不同点是：______
> 下次遇到类似情况应该：______

### Step 3：视角盲区检查（5 分钟）

选本周一个判断或决策，问：

> 我的判断是从什么视角出发的？
> 谁的视角我没有考虑到？
> 如果从那个视角看，我的判断还成立吗？

---

## 流程五：月度评估（每月一次，30 分钟）

### 指标追踪

| 指标 | 本月数据 | 趋势 |
|---|---|---|
| 重要决策中考虑了 ≥2 个方案的比例 | __ / __ | |
| 事后发现"应该考虑但没考虑"的次数 | __ | |
| 因为方案单一导致返工/失败的次数 | __ | |
| 周复盘完成次数（目标 4） | __ | |

### 月度问题

1. 这个月哪个决策如果多想 5 分钟会更好？
2. 这个月有没有一次"跳出固定模式"成功的情况？
3. 下个月最需要改进的一个环节是什么？

---

## 执行节奏总览

| 频率 | 动作 | 时间 |
|---|---|---|
| 每次重要决策 | 强制暂停（流程一） | 3-5 分钟 |
| 每次遇到复杂问题 | 多角度拆解（流程二） | 10-15 分钟 |
| 每次面对大量信息 | 降噪流程（流程三） | 5 分钟 |
| 每周一次 | 周复盘（流程四） | 15-20 分钟 |
| 每月一次 | 月度评估（流程五） | 30 分钟 |

## 渐进式启动

- **第 1-2 周**：只做流程一（决策前强制暂停）。其他先不碰。养成"想到方案后停一下"的习惯。
- **第 3-4 周**：加入流程四（周复盘）。开始追踪自己的模式。
- **第 5-6 周**：加入流程二和流程三。扩展到问题分析和信息处理。
- **第 7 周起**：全流程运行 + 月度评估。

不要试图从第一天就全部做到。渐进式改变比一次性全面铺开更有效。

## 核心原则

这套流程只做一件事：**在你"看到答案"和"执行答案"之间，插入一个暂停。**

快不是问题，**不验证就执行才是问题**。这套流程的目标不是让你变慢，是让你在保持速度的同时增加一个检查步骤——"我确认这是我能看到的最优解吗？"
